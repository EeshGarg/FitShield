# FitShield 0.54 — Play groundwork, with the app-coverage tail closed

**Released:** 2026-07-03

**Play versioning:** `versionName 0.54` ↔ `versionCode 1` — the pair *reserved*
for the first Play upload. No upload has happened. Record every future pair here
per [PLAY_STORE_RELEASE_CHECKLIST.md](../docs/PLAY_STORE_RELEASE_CHECKLIST.md) §2,
at the moment a build is uploaded rather than when one is planned.

## Overview

0.54 finishes what 0.53 started. The Android app-blocking dataset is no longer
"verified where we got to": **every one of the 2,572 tracked brands now has a
researched, verified app status** — a real package mapping, a confirmed
no-app determination, or an explicit shared-platform record. The sweep also
exposed and removed corrupted blocklist imports, including registry namespaces
that could have over-blocked entire country domain spaces. Around the data,
the repository was reorganized so the shared engine, the browser extension,
and the Android app are cleanly separated — and the release signing
configuration landed, so a Play-ready bundle can be produced from this tree once
an operator supplies a keystore. None was produced here.

## Data: full app-coverage parity

- **All 1,280 remaining `needs_review` brands resolved.** Six parallel
  research passes checked every brand against its official store listing
  (brand + developer + market confirmed on the live page — **never guessed**,
  same standard as 0.53). Results:
  - **243 new verified package IDs** — 1,302 → **1,545 packages covering
    1,474 brands**, including major platforms' regional apps (Costa Club,
    Cotti, Carl's Jr., Gong cha, KOI Thé), East-Asian group apps, and
    delivery platforms verified per country.
  - **777 brands verified `no_app`** — a researched terminal status (small
    regional chains, WeChat-mini-program-only brands, defunct services), so
    they are never re-researched.
  - **283 brands marked `shared_app`** — country storefronts and alias
    domains of platform apps (Glovo, PedidosYa, Deliveroo, Wolt, foodpanda,
    Bolt Food, Subway, …). The package is recorded once, on the owning brand,
    so every package ID still maps to exactly one brand.
  - Only **38 brands remain `needs_review`** (genuinely ambiguous ownership,
    e.g. delisted apps or unverifiable regional operators).
- **Dataset schema v-next:** `packageStatus` gains the two verified terminal
  statuses `no_app` and `shared_app`; the validator, generator, audits, and
  tests enforce and report them. `active` still requires at least one package;
  all non-active statuses require none.
- **Removed 10 corrupted blocklist imports** the sweep exposed — non-food
  entities (ea.com is Electronic Arts; cheesecakelabs.com is a software
  agency; haema.de is a blood-donation service; joongang.co.kr is a newspaper;
  fishwindow.com is a window-cleaning company; bbqnation.com is not the
  Barbeque Nation chain, which stays covered via barbequenation.com) and,
  more importantly, **registry namespaces** (`com.ao`, `com.ls`, `uk.com`,
  `ta.com`) whose apex-or-subdomain matching could have blocked every site
  under those country namespaces. Accuracy fix: FitShield should never
  over-block. Fast-food dataset bumped to **v1.2** (2,111 entries); the
  generated Android rules asset is now **2,575 hosts**.

## Repository: engine / extension / android separation

- The shared canonical engine now lives in **`engine/`** (`blocklist.js`,
  `blocklists/`, `data/`); the browser extension source in **`extension/`**
  (manifest, pages, `_locales/`, `icons/`); the Android-authored WebView shim
  in `android/web-src/`. Store documents moved under `docs/`.
- **Nothing shipped changed shape:** the packaged zips keep the exact same
  internal layout (verified entry-for-entry against a pre-move baseline), and
  the Android rules asset kept its host list and hash. All 111 file moves are
  git renames, so history follows every file.
- **Developer note:** the repo root is no longer a loadable unpacked
  extension. Run `node build.js`, then load `dist/chrome` or `dist/firefox`.

## Play Store release

- Version 0.54 is the first build *intended* for Play upload. What landed is the
  **configuration** for one: a release signing config that reads a gitignored
  `keystore.properties` (and leaves the build unsigned when none is supplied), an
  API 35 target, debug-gated logging, and the launch document pack under
  [docs/](../docs/).

  > **Corrected 2026-08-26.** This section originally claimed a "signed release
  > AAB from the committed pipeline". There was none, and there still is none:
  > nothing in `tools/build-android.js` runs `bundleRelease` — it builds a debug
  > APK — and signing needs a keystore only the operator holds. The bundle is a
  > hand-run command, documented in the release checklist §3 and marked HUMAN.
  > `test/play-release.test.js` now fails if any document claims otherwise.

- The remaining steps are Console-side (organization account, declarations,
  listing assets, staged rollout) and every one of them is now a checkbox in
  [PLAY_STORE_RELEASE_CHECKLIST.md](../docs/PLAY_STORE_RELEASE_CHECKLIST.md).

## Validation

- `npm test` — 73 tests; `npm run validate` — 9 audits, 0 errors, including
  the engine-parity audit (2,575 hosts match the separated engine), the
  app-package dataset audit (schema, orphans, duplicates, drift,
  determinism), and the Play-release checks.
- Every new package ID carries a store-listing evidence URL in the research
  record; contested platform packages were resolved to a single owning brand
  deterministically.

## What 0.54 deliberately does NOT do

- No Play Console submission from the repo — uploading, declarations, and the
  staged rollout are operator actions (see the checklist's ⚙️ items).
- The 38 remaining `needs_review` brands stay unresolved rather than guessed;
  they are the 0.55 data tail.
- Blocklist metadata quality (a cluster of wrong `countries: ["JP"]` tags and
  similar import artifacts flagged during the sweep) is noted for a dedicated
  audit pass — entries remain functional for blocking either way.
