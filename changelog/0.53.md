# FitShield 0.53 — The native Android app

**Released:** 2026-07-02

## Overview

0.53's mission was **one product, two platforms**. FitShield now ships as a
native Android app (preview) alongside the browser extension — built by reusing
the extension's actual web code, engine, and canonical data rather than
rewriting anything. The release closes the extension↔Android feature-parity
loop, expands the app-blocking dataset with verified (never guessed) package
IDs, and lays the release engineering groundwork for a Google Play launch.

## Major features

### Native Android app (preview)

- **One web UI, two platforms.** The Android app hosts the same HTML/CSS/JS the
  extension uses, in a WebView behind a platform-agnostic `fitshield.*` API
  (`browser-shim.js` ↔ `android-shim.js`). Dashboard, stats, recipes, currency,
  full theme customization, the living ambient background, and all **83
  locales** run verbatim. See [docs/ANDROID.md](../docs/ANDROID.md).
- **Website blocking via a local connection filter (TLS SNI / HTTP Host).** A
  local `VpnService` reads only the cleartext destination host the client
  already sends, resets blocked connections, and relays everything else
  byte-for-byte to the client's chosen destination over `protect()`ed sockets.
  **Not** a DNS filter: it coexists with strict Private DNS / NextDNS, never
  intercepts or alters DNS, never decrypts HTTPS, and tunnels nothing to any
  server. Verified on-device (Samsung, Android 14).
- **Native app blocking (opt-in AccessibilityService).** Opening a blocked
  food app shows a native FitShield pause screen (`BlockActivity`) — branding,
  block reason, category-aware messaging, schedule status, stats,
  category-matched vegetarian + meat recipe ideas, a 60-second reflection
  timer, temporary unlock, and a localized "Learn more" → fitshield.net. The
  service reads **only the foreground package name** (never screen content) and
  survives process kills; the block screen sends the blocked app home first so
  it can't steal the foreground back.
- **Verified app→package dataset: 33 → 870 mappings.** Every Android package ID
  was confirmed against its official Google Play listing (brand + developer +
  market); unknown ones remain `needs_review` — **never guessed**. Deterministic
  generation, validated for schema/orphans/duplicates/drift, bundled as a slim
  asset (only verified mappings ship in the APK).
- **Optional hardening, all off by default:** "display over other apps" (more
  reliable pause screen), an "extra reliability" keep-alive foreground service
  (quiet minimal notification, does no work), and battery-optimization
  guidance — each with a plain-language explanation and live status indicators
  (Accessibility / VPN / overlay).
- **Edge-to-edge One UI look:** transparent status and navigation bars with the
  app gradient behind them, safe-area-aware content.

### Extension improvements

- The block page now honors **`prefers-reduced-motion`** (the countdown ring
  stops animating; the number still updates).
- Both block screens gained a localized **"Learn more" link to fitshield.net**
  (new `learnMoreBody`/`learnMoreLink` keys across all 83 locales).

### Play Store groundwork

- **Android 15 (API 35)** target/compile SDK, AGP 8.6, injectable
  `versionCode`, and a signing config that reads from a gitignored
  `keystore.properties`. What landed is the *configuration*: with a keystore
  supplied, `./gradlew :app:bundleRelease` produces a signed **AAB**. No such
  bundle was built or uploaded, and no repository command builds one — see
  [PLAY_STORE_RELEASE_CHECKLIST.md §3](../docs/PLAY_STORE_RELEASE_CHECKLIST.md#3-signing-and-the-release-bundle).
- **Release hygiene, audit-enforced:** WebView remote debugging, console
  logging, and per-connection logging are debug-only (`BuildConfig.DEBUG`) — a
  release build writes **no hostnames or filtering decisions to logcat**.
  `tools/android-audit.js` fails if the API level drops below 35 or debugging
  is unguarded.
- **Launch document pack:**
  [PLAY_STORE_RELEASE_CHECKLIST.md](../docs/PLAY_STORE_RELEASE_CHECKLIST.md),
  [PRIVACY_POLICY_ANDROID_NOTES.md](../docs/PRIVACY_POLICY_ANDROID_NOTES.md) (Data
  safety: nothing collected, shared, or transmitted; prominent
  Accessibility/VPN disclosures), and
  [STORE_LISTING_DRAFT.md](../docs/STORE_LISTING_DRAFT.md).

## Data & docs

- New additive datasets `data/android/*-apps.json` (brandId → packageIds only;
  blocklists stay authoritative and untouched) with generator, validator, and
  porter tools; the bundled APK asset is drift-checked against a fresh build.
- `docs/ANDROID.md` fully reconciled with the implementation (connection-filter
  model, opt-in accessibility, permissions table, intentional Android
  deviations from the extension documented in §2c).
- README/manifest comments updated to the SNI framing; dead pre-WebView native
  UI resources removed.

## Validation

- `npm test` — 73 tests; `npm run validate` — 9 audits including the Android
  engine-parity audit, the app-package dataset audit, and the new Play-release
  checks. Browser packages and the **debug APK** build from the one source tree;
  the release AAB is a hand-run Gradle task that needs a keystore, and was not
  built here.
- On-device verification (Samsung, Android 14): site blocking with Private DNS
  on, app blocking (block → not-now / open-anyway / re-block, non-food apps
  ignored), keep-alive opt-in lifecycle, overlay flow, edge-to-edge UI,
  localized block buttons (German), and the fitshield.net link opening the
  external browser.

## What 0.53 deliberately does NOT do

- No Play Store submission yet — 0.53 is the release-engineering foundation;
  the store rollout (keystore, Console declarations, listing assets, staged
  rollout) is the 0.54 track.
- IPv6 is captured and dropped (forces IPv4) — IPv6-only networks are not yet
  supported; documented in docs/ANDROID.md §7.
- No boot auto-start of the VPN (no `RECEIVE_BOOT_COMPLETED`) — re-enabling
  after reboot is a deliberate user action.
